# 商店黑屏完整说明（含「1.57→1.58 更新当天就黑」这条线索）

> 时间线：2026-11-10 17:01（1.57→1.58 首次装 v1.3 数据）→ 22:29（换 v1.4）→ 23:06 复现 → 23:07 修好
> 结论先行：**两个不同的问题被同一条「旧表不删」的设计缺陷串在一起**。

## 一、先回答你的问题：v1.4 有没有删掉商店的汉化？

**有，但只删了「主数据表」这一层，界面文本那一层还留着。**

v1.4 的 70 张表里，跟商店有关的一共只有 `BattlePassProductMaster`（通行证商品）。
v1.3 有的 5 张商店表，v1.4 全都不带了：

| 表 | v1.3 大小 | v1.4 |
|---|---|---|
| `FeatureProductShopMaster` | 173,136 | ❌ 不带 |
| `ValuePackShopMaster` | 977,440 | ❌ 不带 |
| `ValuePackShopSubCategoryMaster` | 8,128 | ❌ 不带 |
| `PayShopMaster` | 1,504 | ❌ 不带 |
| `CostumeShopSubCategoryMaster` | 624 | ❌ 不带 |

但**商店界面上的中文标签还在 bundle 里**（我扫过：v1.3 有 6 个 bundle 含「商店」、17 个含「购买」，
v1.4 还有 3 个含「商店」、15 个含「购买」）。所以你在商店里看到的 `ショップ` / `Purchase Now` 混排，
是**界面文本来自官方包、动态内容来自主表**的正常结果——不是 v1.4 删漏了。

顺带一个发现：`ショップ` 这个日文标题是**官方 APK 自带的**，在
`assets/bin/Data/1b4d15f3d50224726ac2a1153b296cca` 里，原文是
`APP_SHOP_TITLE_NAME,ショップ,Shop,,` —— 这是游戏的日/英双语文本表，汉化补丁没碰它。
1.57 和 1.58 的这个文件**逐字节相同**（75,832 B），所以标题显示日文跟版本更新无关。

## 二、你说的「1.57→1.58 更新时就黑了」——这才是关键线索

我去翻了设备上的 `install.log`，时间线是这样的：

| 时间 | 事件 | 结果 |
|---|---|---|
| 11-09 19:57 | 装 1.57.0 的 cn-fps 包 | — |
| **11-10 17:01** | **装 1.58.0 包，首启解包 v1.3 数据（84 张表全写）** | ← 商店从这时开始崩 |
| 17:04 / 17:10 | 重启两次（快路径，不解包） | — |
| 22:29 | 换 v1.4 包，解包 70 张表（**旧的 84 张没删**） | 还是崩 |
| 23:06 | 我复现，抓到 `NullReferenceException` | — |
| 23:07 | 删 5 张旧商店表 | ✅ 好了 |

**根因在 17:01 就埋下了**，不是 v1.4 引入的：

1. 你在 1.57 时代装过 v1.3 数据 → `files/cache` 里有 84 张**1.57 版**的主表
2. 游戏更新到 1.58 → **客户端代码换了，但缓存里的旧表游戏不会主动清**
3. v1.3 数据包又把 84 张 1.57 版表**原样重写了一遍**（它本来就是给 1.57 做的）
4. 游戏用 1.58 的代码去读 1.57 的 `FeatureProductShopMaster` → 分类 ID 对不上 → 空引用 → 黑屏

v1.4 只是「没把旧的 5 张商店表删掉」，所以**继承了**这个崩溃，不是它造成的。

## 三、为什么偏偏是商店？

`ShopCategoryToggle.UpdateToggle()` 会遍历「商店分类」列表，对每个分类去查商品表。
1.57 的商品表里有 1.58 已下架/改名的分类（比如活动限定商店），查回来是 `null`，
代码没做空判断 → `NullReferenceException` → 整个 `ShopFeaturePanel` 的协程挂掉 → 面板没渲染 → 黑屏。

任务面板（`課題`）没崩，是因为 `MissionMaster` 那张旧表恰好还能被读通（虽然结构变了），
只是显示英文——**属于运气好，不代表没问题**。

## 四、为什么「删掉就好」——游戏的自我修复机制

删掉那 5 张表后，游戏下次需要时会**自己重新下载官方 1.58 原版**。实测证据：

| 表 | v1.3（汉化版） | 游戏重下的 1.58 版 |
|---|---|---|
| `FeatureProductShopMaster` | 173,136 | **176,048**（23:11） |
| `ValuePackShopMaster` | 977,440 | **986,288**（23:07） |
| `ValuePackShopSubCategoryMaster` | 8,128 | **8,176** |
| `PayShopMaster` | 1,504 | **1,440** |
| `CostumeShopSubCategoryMaster` | 624 | **608** |

五个大小全都不一样 → 证明 1.58 的商店表结构和 1.57 的汉化版**确实不同**。
下载回来的是正确版本 → 商店正常（英文，符合 v1.4 设计）。

这也说明：**主表走的是 `File.Exists` 判定**（见 `CN_DATA_SPEC.md` §5.2 的反汇编结论），
文件不在就重新下载，不会报错。

for f in eafcfa27c264287176ad6e85b9e1bc75 19932e1fedb57097193b60498d72b158 \
         266ece11033ebd73a275ab7a8d4a0663 7010a0a2674fb222a58d5efb6783c292 \

## 六、根本修法（要改代码，等你点头）

`CnSetupActivity` 现在的策略是「只覆盖、不删除」——v1.3 时代 84→84 没问题，
v1.4 变成 84→70，多出来的就必须清。改法：

1. 解包时把本次写入的 master 文件名记到 `files/tlw_cn/installed.list`
2. **下次解包前**，把 `installed.list` 里有、但这次数据包里没有的表删掉
3. 只删「自己写过的」，绝不碰游戏自己下载的文件
4. 同理清理 `UnityCache/Shared` 下已不在数据包里的 `<A>/<B>`（v1.4 的 345 个 A 目录和 v1.3 相同，这次没触发）

这样以后上游再改表数量，老用户升级也不会踩坑。要我改的话说一声，改完重新出包。

## 七、给你的判断依据（一句话版）

- **v1.4 删了商店的主表汉化**（5 张），这是设计（Release 说明里写了「交换所/商店保持英文」）
- **商店黑屏不是 v1.4 造成的**，是 1.57 的旧表在 1.58 客户端上跑崩的，v1.4 只是没顺手清理
- **删掉旧表就正常**，游戏会自己下回官方版；代价是商店/任务变英文
- **要根治必须让安装器会删旧表**，否则下次更新还会再来一次
